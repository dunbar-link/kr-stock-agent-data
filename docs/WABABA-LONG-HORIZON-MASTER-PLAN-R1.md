## 1. 백테스트 엔진 (PHASE 2 — 구현 완료)

`scripts/research/backtest_engine.py` (계산 전용 · 네트워크 0 · 파일 write 0)

### 재현 단위

```
date t → 그 날 상장 종목(스냅샷) → 그 날 KRX 공표 PER/PBR/EPS/BPS
       → ROE=EPS/BPS · EarningsYield=1/PER
       → profitabilityRank + valueRank = combinedRank
       → 상위 N 종목 동일가중 매수(배치)
       → hold_months 후 배치 전량매도 → 매도대금 + 신규 적립금 재투자
```

모든 거래에 `decision date · 체결가 · 수량 · 수수료 · 세금 · 현금 · NAV` 가 남는다.
난수 없음 → **같은 입력이면 같은 결과**(self-test `deterministic` 항목으로 강제).

### 이미 검증된 것

| 검사 | 결과 |
|---|---|
| 결정성(같은 입력 → 같은 NAV 시계열) | PASS |
| 랭킹 산출(2026 스냅샷 2,770행) | 적격 **1,495~1,520** 종목 — 정상 |
| 1999~2002 스냅샷 | 적격 **0** — BPS 결손 확인(§데이터 문서와 일치) |
| NAV 양수 유지 / 평가 지표 산출 | PASS |

### 비용·세금 모델 (원전 대비 개선점)

```
매수  수수료 15bp
매도  수수료 15bp + 증권거래세 20bp
민감도  COST_ZERO(0) / COST_BASE(15+20) / COST_HIGH(30+20)
```

현재 운영은 `FEE_TAX_MODELED = False`(0 가정)다. 50거래일 회전은 **연 약 5회전**이므로
왕복 50bp × 5 = **연 2.5%p** 가 사라진다. 이 항목만으로 전략 판정이 뒤집힐 수 있다.

### 상장폐지 처리

보유 중 종목이 스냅샷에서 사라지면 **마지막 관측가 × (1 − haircut)** 로 청산한다.
`DELIST_0 / DELIST_30 / DELIST_100` 3가지를 필수 민감도로 돌린다.
`delistEvents` 건수를 항상 보고한다(숨기지 않는다).

## 4. 전략 선정 규칙 (PHASE 6 — 최고 CAGR 을 뽑지 않는다)

**PEAK 이 아니라 ROBUST PLATEAU 를 찾는다.**

채택 조건(모두 충족해야 함):

1. 인접 파라미터(보유기간 ±1칸, 종목수 ±1칸)에서 **CAGR 이 급락하지 않는다**
   → 특정 값만 압도적이면 과최적화로 간주하고 **탈락**시킨다.
2. COST_HIGH 에서도 동일가중 시장 benchmark 를 **초과**한다.
3. 5년 하위구간 중 **과반**에서 benchmark 초과.
4. 시작월 12회 shift 전부에서 결론이 유지된다.
5. MDD 와 최장 수중기간(underwater months)이 **일반인이 견딜 수 있는** 범위다.

> 판단 원칙: **CAGR 1%p 더 높은 전략보다, MDD 가 10%p 낮고 규칙이 단순한 전략을 택한다.**
> 이 서비스의 실패 모드는 "수익률이 낮은 것"이 아니라 "사용자가 중간에 그만두는 것"이다.

### 4-1. benchmark (절대수익만으로 성공이라 하지 않는다)

```
① KOSPI 지수                     ② KOSDAQ 지수
③ 동일가중 시장 포트폴리오        ← 같은 universe 필터, 순위만 미적용 (구현 완료)
④ 단순 buy-and-hold
```

③이 핵심이다. **"복잡한 마법공식을 쓸 이유가 있었는가"** 는 ③ 대비 초과수익으로만 답할 수 있다.

### 4-2. 평가 지표 (구현 완료)

```
TWR CAGR(시간가중) · IRR(금액가중, 적립식 필수) · 총수익 · MDD · MDD 발생일
변동성 · Sharpe · Sortino · 최장 수중기간(개월)
rolling 1y / 3y / 5y (min · p10 · median · p90 · max · 마이너스 비율)
회전율 · 거래횟수 · 비용총액 · 비용/납입금 비율 · 상장폐지 이벤트 수
```

적립식은 CAGR 이 왜곡되므로 **TWR 과 IRR 을 분리 산출**한다(엔진에 이미 반영).

## 5. Forward Test 설계 (PHASE 7)

### 원칙: 기존 50일 포트폴리오를 덮어쓰지 않는다

```
LEGACY_50D              현재 운영 중인 공개 모의장부 — 그대로 보존(legacy experiment)
NEW_CANONICAL_STRATEGY  백테스트로 선정된 규칙 — 별도 장부로 신규 개시
```

두 장부를 **최소 12개월 병렬 관찰**한 뒤에야 전환을 논의한다.
전환은 Founder 승인 게이트다. 자동 전환 금지.

### 중요한 사실 (홈페이지 표기에 직결)

현재 운영은 **TDI 29 / seq 27** 이고 첫 만기 매도는 **TDI 51** 이다.
즉 **아직 한 사이클도 완료되지 않았고 매도 실적이 0건**이다.
지금의 평가손익은 "50거래일 회전 전략의 성과"가 아니라 **매수 누적 구간의 평가액**일 뿐이다.
→ 홈페이지에서 이것을 전략 성과로 제시하면 **사실상 허위 표시**가 된다.

### 신규 장부 개시 조건

1. 백테스트 PHASE 4·5 완료
2. §4 채택 조건 5개 전부 충족한 규칙 확정
3. Founder 승인
4. 개시 시점·초기자본·적립액·규칙을 **사전 공표**하고 이후 변경하지 않는다
   (사후에 규칙을 바꾸면 forward test 가 무의미해진다)

## 9. 남은 실행 순서 (재개 지점)

```
1. KRX 조회 복구 확인
2. python scripts/research/build_pit_snapshots.py --start 2007-01 --end 2026-08 --sleep 0.5
     → 약 236개월 · 700콜 · 10분
3. python scripts/research/run_backtest_matrix.py --mode selftest
4. python scripts/research/run_backtest_matrix.py --mode baseline --out reports/research/baseline.json
```
